# 朴素版课件编写规范（第四章 · 按《数字货币3.pptx》风格）

**目标**：把“精美版”（`数字货币4_优化版.pptx`，127 页，内容已获用户认可）的**内容**，用《数字货币3.pptx》那种**朴素风格**重新排版。
内容不删减、不改结论，只改呈现；备注（讲稿）保留全部教学信息。

## 1. 允许的版式语汇（只有这些）

| 元素 | 规则 |
|---|---|
| 背景 | 白底，无任何装饰、页脚、页码 |
| 标题 | 左对齐、楷体粗体（库自动处理）；短名词或短结论 |
| 正文 | Times New Roman + 楷体，20–28pt（库自动选字号），左对齐，圆点/短横列表 |
| 强调 | **只有一种**：红色粗体（`[[ ]]`）；整句红字用 `!! ` |
| 表格 | 藏蓝表头白字、白/浅灰交替行、浅灰细边框（库自动生成） |
| 图片 | 原课件截图（`build/assets/*.png`）或 `charts.py` 生成的朴素图表，下方（或左/右）配一两句说明 |

**不要**：卡片、图标、emoji、色块、彩色（除红）、形状/箭头、章节分隔页、背景图、渐变、阴影、斜体花样。

## 2. 接口速查（`plain.py`，参考 `content/p1_intro.py` 的写法）

```python
def build(d):                       # 每个 content/pX.py 提供 build(d)
    d.text('标题', [行…], notes='…', src='14')                    # 文字页
    d.table('标题', ['列1','列2'], [[…],[…]], widths=[2,5],        # 表格页（widths 为相对比例，可省略）
            lead=['表上方的导语（可选）'], foot='表下方红色粗体收束句（字符串或列表）',
            notes='…', src='15')
    d.pic('标题', 'merkle4.png', ['说明行…'], layout='top'|'left'|'right',   # 图片页
          max_size=22, notes='…', src='16')                       # 多图并排：img=['a.png','b.png']（仅 top）
```

`items` 的行首标记：

| 写法 | 效果 |
|---|---|
| `"正文"` | 普通段落（无符号） |
| `"# 小标题"` | 粗体段落 |
| `"- 要点"` | 一级圆点 • |
| `"#- 要点"` | 粗体一级圆点（后面常跟二级） |
| `"-- 子要点"` | 二级短横 –（字号小一档） |
| `"!! 文字"` | 整段红色粗体（“思考/启示/关键”收束句） |
| `""` | 空行 |

行内标记：`[[红色粗体]]`　`**粗体**`　`^{上标}` `_{下标}`（如 `2^{256}`、`H_{2}O`）　`` `等宽` ``（哈希值、地址）。
表格单元格同样支持行内标记，单元格内 `\n` 为换行。

其他参数：`d.text(..., size=24)` 强制字号；`max_size=24` 限制上限；`spc=12` 段间距（课堂讨论/小测可用 12–14）；`anchor='t'` 顶部对齐（默认居中，与 3.pptx 一致）。
`src='14'` 或 `src='14,15'`：记录这页对应精美版第几页（用于生成新旧页码对照，**每页都要写**）。
图表：`from charts import bar, line`；`path = bar('名称', labels, values, ylabel=…, fmt='{:.1f}%', highlight=[0])` → `d.pic('标题', path, [...])`。

## 3. 篇幅与排版规则

1. **一页一个结论。** 标题 ≤ 18 字最佳（超过 22 字就缩短）；标题不加序号、不加装饰符。
2. 文字页正文 ≲ 200 字（约 8–10 行）；构建日志里字号 < 22 说明太密：删减、拆页，或把细节挪进备注。**正文最小 20pt，表格最小 14pt。**
3. 每页**最多一句**红色整句收束（`!! `），不要每页都有；`[[ ]]` 强调只给关键词/数字，每页 ≤ 5 处。
4. 列表最多两级。长句拆成短句；一条要点 ≤ 40 字。
5. 表格 ≤ 8 行 × ≤ 4 列、单元格 ≤ 30 字（超出会自动缩字号，< 14pt 时请拆表）。
6. **孤字行**（某段最后一行只剩 1–2 个字）构建时会报 WARN，渲染检查也会报；改措辞/删几个字即可。构建 WARN 必须清零。
7. 数字与中文之间不加空格；大数用“万/亿”；保留英文名词原文（如 Merkle tree、nonce）。
8. 不引用页码（“见第 N 页”）——改成“前面讲过/后面会讲”。
9. 图片页：图 + 1–3 句说明；来源写进备注“来源/图片来源”。

## 4. 从“精美版”到“朴素版”的转换映射

| 精美版元素 | 朴素版写法 |
|---|---|
| 章节分隔页（大号序号 + 图标 + 一句话） | **不单独做分隔页**。改成一页文字页，标题＝章节名（如“积木一：密码学与公私钥”），正文＝一句引导问题 + 本节要点/对应“四个要求”中的哪几条；原分隔页备注并入这页备注 |
| 三/四张“卡片” | 圆点列表（`#- ` 粗体小标题 + `-- ` 说明），或 2–4 列表格 |
| 大数字/统计块 | 句中红色粗体数字，或表格一列 |
| “关键结论”橙色条 / callout | 页尾一句 `!! ` 红色粗体（思考/启示/联系/关键问题） |
| 时间线、流程箭头 | 表格（日期｜事件）或编号步骤 `1. 2. 3.`；若原课件有现成示意图，用图片页 |
| 对比（左右双栏） | 表格 |
| 流程/结构图（精美版里手绘的） | 编号步骤；或用 `build/assets` 里的原课件图；或 `charts.py` |
| 原生图表 | 优先小表格；确有价值才用 `charts.py` 画朴素 PNG（藏蓝/红、白底） |
| 随堂小测（选择题/判断题） | 文字页，标题“随堂小测：xxx”，`spc=12`；题干编号，选项写在同一段（A.…　B.…）；**答案与解析放备注**（小标题“答题线索”） |
| 页面底部小字“来源：…” | 移到备注（小标题“数据来源”/“来源”）。来源本身是教学内容时才留在页上 |
| 术语表、参考文献 | 表格（术语｜解释）；参考文献用文字页小字号（≥ 18pt），必要时拆两页 |

## 5. 备注（讲稿）规范——沿用 3.pptx 的做法

- 精美版备注里的每一条教学信息都要保留（讲解、提问、追问、数据、故事、史实更正、答案…），可以微调措辞使之更像讲稿。
- 格式：**小标题独占一行，正文另起一段**。直接沿用精美版的“【讲解】正文”写法即可，库会自动转换成“讲解↵正文”。
- 常用小标题：讲解 / 引导 / 提问 / 追问 / 过渡 / 数据 / 数据来源 / 来源 / 图片来源 / 史实更正 / 故事 / 课堂活动 / 答题线索 / 延伸 / 教学提示 / 风险提示。
- 原课件里的错误，沿用“史实更正”小标题并写清“原课件写了什么 → 正确是什么”。
- 备注用纯文字，不用 emoji、不用表格；段落 3–5 句为宜。

## 6. 质量门槛（每个文件交付前）

1. **事实不变**：数据、日期、人名拼写、公式与精美版一致。如发现精美版本身有错：改正，在备注“史实更正”里写明，并在最终汇报里告诉主会话。
2. 全部精美版页面的内容都要落到某一页（分隔页除外）。允许合并/拆分，但每页都要有 `src`。
3. `build.py` 无 WARN；`check_pdf.py` 无问题；逐页看过渲染图（联系表），确认无溢出、无遮挡、无孤字、图片清晰。
4. 不要修改 `plain.py` / `build.py` / 别人的 `content/*.py`；缺能力就用现有接口变通，并在汇报里写明需求。

## 7. 工作流程

```bash
cd /home/user/ppt/build_plain
python3 build.py --parts p2_keys,p3_hash --out out/F1.pptx          # 只构建自己的部分
python3 render.py out/F1.pptx render/F1 70 12                        # 渲染并生成联系表 render/F1/sheet_01.jpg …
python3 check_pdf.py render/F1/F1.pdf                                # 自动查孤字、溢出、压标题
pdftoppm -r 110 -f 5 -l 5 -jpeg render/F1/F1.pdf /tmp/F1_p5          # 放大看某一页（页号含封面）
```

注意：封面算第 1 页，所以部分构建时第一页内容是第 2 页。精美版对照材料：`gen/fancy.md`（精美版全文+备注，按“<!-- Slide number: N -->”分页）和 `../build/parts/*.js`（原始规格：图片文件名、数据）。
图片素材清单见 `../build/assets/manifest.json`；`grep -n "img(" ../build/parts/p2_keys.js` 可查某页用了哪张图。

## 9. 补充说明（整本合并后的经验）

- 圆点项目符号始终为黑色（库里固定了 `buClr`），所以 `"- [[关键词]]：…"` 这种以红字开头的条目也不会出现红圆点。
- `table(foot=…)` 里的普通字符串会变成**红色粗体**；要黑色脚注，给该条加 `"- "` 或 `"# "` 前缀（`foot` 可传列表）。
- `table()` 会在你给的列宽附近自动微调，尽量消除单元格里的“孤字”（末行只剩 1–2 字）并压低表高；所以 `widths` 只需给大致比例。
- 构建时估算折行同时按 PowerPoint 和 LibreOffice 两种方式做（LibreOffice 在中西文交界会多出约 0.25em 间距，弯引号也更窄），两种都放得下才算通过。
- 质量检查脚本：`check_pdf.py`（孤字、溢出、压标题、压表格）、`lint.py`（残留标记、页码引用、emoji、过长标题、空备注）、`factcheck.py`（与精美版逐页比对数字与英文术语是否保全）、`finalize.py`（修正 app.xml 与缩略图）。
- 行内的上标/下标字号会缩小（约 65%），`check_pdf.py` 里出现 10–14pt 的字符都是上标，属正常。
